# v2026.11.22-10 乗員経路探索のワーカー化・禁止ブロックの内部データ除去

通常の乗員経路探索を2本の専用ワーカーへ移しました。メインスレッドは読み込み済みのワールドから衝突情報を少しずつ取得し、ワーカーは数値配列だけで経路を探索します。結果を採用するときに現状を確認し、NPCの移動自体は従来どおりメインスレッドで行います。Sableの船内座標として経路を認識する指定も付与します。

探索範囲・訪問数・実行時間・待機数には上限があります。1経路の訪問上限は32,768、ワーカー探索時間の目安上限は25msです。衝突情報の取得はサーバー全体で1tick約2msを目安に分割します。単発の衝突形状計算やGCを強制中断する制限ではありません。経路が見つからない場合やキュー混雑時は、重い同期探索へ戻りません。

平面だけでなく高低差・梯子・複数の到達候補を扱う3次元の探索です。ただし元の探索アルゴリズムとは異なるため、特殊ブロックや複雑な船内の全経路で同じ結果になる保証はありません。水中経路や非常に広い探索範囲は保守的に不許可になる場合があります。

`config/aerocannons-performance.toml` の `crewAsyncNavigation = true` が初期値です。`false` にすると通常探索は元の同期方式になります。変更後は再起動してください。

試合用スケマティックからクリエイティブブロックを取り除く際に、そのブロックの内部データ参照も削除し、残すブロックの参照番号を振り直します。内部データ配列も詰め直すので、削除したモーターのデータが空気ブロックへ復元されません。Createの構造体内の禁止ブロックも、内部データを含むブロック項目ごと取り除きます。

## 導入

ホストを終了してワールドをバックアップし、旧Aero Cannons JARを取り出して今回のJARに差し替え、再起動してください。旧版と新版を同時に入れないでください。通信形式の変更はありません。

ドック生成の停止対策（v2026.11.22-9）と、それ以前の変更も含みます。

## 確認した範囲

別環境の専用サーバーで起動し、通常のfindPathから到達可能な20ノードの経路が返ること、専用ワーカーの生成、実際のSable船上NPCが短い経路で目標付近まで移動することを確認しました。禁止モーターの内部データ除去と、有効なチェストの内部データ保持・参照番号の振り直しも確認しました。3次元グラフの段差・梯子・到達不能・訪問数上限・期限は独立試験を通過しています。大人数を乗せた実艦での長時間試験、梯子や特殊ブロックを使った実移動の網羅試験までは未実施です。
