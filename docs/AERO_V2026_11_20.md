# v2026.11.20 — unchanged snapshot suppression

Unchanged decal scenes were cleared and resent every five seconds, and unchanged ship-water room lists were resent every five ticks. The server now skips identical snapshots. Changed data keeps the existing cadence and packet format; there is no deliberate added delay for block actions, target commands or changed visual states. Sable UDP, entity movement, vanilla chunk data and gameplay physics are unchanged.

- Decals: retain a SHA-256 fingerprint of the visible snapshot, including PNG bytes and dimension. Periodic identical snapshots send nothing and no longer trigger client mesh clears. Placement changes, deletions, visibility changes and asset changes still send the existing full clear-and-replace snapshot. Explicit synchronization forces a full refresh, including PNG data, to recover a client cache.
- Water: compare immutable room snapshots per player and dimension. Identical rooms, including empty snapshots, send once; changed water state or an empty replacement still sends. Per-player cache uses weak keys, so a new connection gets an initial snapshot.
- Disconnection removes the decal cache. The cache stores fingerprints instead of a duplicate PNG/scene per player.

## Verification
Cold-started the candidate in the isolated NeoForge server. An unspawned fake player with a capture connection exercised actual send methods without an Internet transfer.

- 61 identical snapshots produced only the initial send.
- A 256-face decal fixture sent41,874 uncompressed payload bytes initially. Sixty suppressed periodic copies would have contained1,660,680 bytes without cached PNG data.
- A100-room water fixture had12,001 uncompressed payload bytes;60 identical repeats (720,060 bytes) were suppressed.
- Placement change/deletion, explicit PNG cache repair, logout, fingerprint dimension/content changes (including equal32-bit array hashes), changed water/empty/reconnect, and unchanged packet-codec round trips passed.
- JAR CRC, all JSON/TOML/resource references, allowed changed classes and absence of bundled probes passed. Built by compiling the affected sources against the mapped dependencies and updating the verified base JAR; a complete Gradle build was not run.

These are synthetic payload counts before Minecraft compression, TCP/IP headers and real traffic. They do not establish total bandwidth savings, moving-ship client rendering or nighttime packet-loss improvement. Continuously changing water still needs synchronization. The same payloads remain readable by v16 clients.
