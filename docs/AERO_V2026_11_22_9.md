# v2026.11.22-9 試合用ドック生成の停止対策

## 修正

試合用ドックの地面を設置する前に、対象チャンクと周囲8チャンクを通常の読み込みチケットで準備します。準備中はそのtickの生成を保留し、チャンクの読み込み完了をメインスレッドで待ち続けません。

地面はチャンク単位で生成し、1回の処理は約2msを目安に分割します。単発のブロック更新やGC自体を強制中断するものではありません。上限4096ブロックも併用します。既に同じ地面がある場所は再設置せず、生成終了時は読み込みチケットを解除します。中断されたチケットにも有効期限を設けています。

クラッシュ報告にあった `MatchMap.Builder.step → Sable物理更新 → チャンク読み込み待ち` の経路で、未読み込みの周辺チャンクへ進まないようにした修正です。C2MEやSable全体の不具合をすべて解消するものではありません。

## 導入

1. ホストを正常終了し、ワールドをバックアップします。
2. `mods` の旧 `aerocannons-*.jar` を取り出し、今回のJARを1個だけ入れます。
3. 再起動します。未完了のドック生成は残っている地面を確認しながら進みます。

ワールドの削除や、監視タイムアウトの無効化は不要です。通信形式の変更はありません。参加者側も同じバージョンにそろえる場合は配布ZIPを利用できます。

これまでの編隊、駐機場所、信管・爆弾などの変更も含みます。本番サーバーと参加用インスタンスへの差し替えは、この配布作業では実施していません。

## 動作確認

本番とは別の専用サーバー（Sable 2.0.5・C2ME 0.4.0-alpha.0.124・NeoForge 21.1.258、メモリ3 GiB）で、未生成チャンクから通常サイズのドック2基（計2,107,400か所）の生成完了を確認しました。チャンク境界の小規模床は全1,444ブロックを照合し、負の座標での拡張生成、既存地面を再処理する経路も通過しました。
