# v2026.11.23-11 — 次回更新用（本番未適用）

CBC Military Supplement 3.0.7のHE/APHEロケット、連装HE/APHEロケット、徘徊型HE/APHEロケットを整備員の再装填対象に追加。

- 組み立て済みラックでは、機体やラックをディスアセンブルせず、元の内部スロットへ戻す。
- ブロックとして取り付けたロケットも、爆弾と共通の再取り付け処理で戻す。
- 発射前と機体設定の取得時に、搭載位置・元の向き・信管の要否を記録する。以前すでに失われて記録もない搭載物は推測で復元しない。
- 母艦の在庫から実物のロケットを1個消費する。元の搭載物に信管が必要で、補給したロケットに付いていない場合は、実物の信管も1個消費して登録済み設定を戻す。
- 飛行中（補給要求時を除く）や発射信号が入ったままの再装填を拒否する。整備員の自動作業は既存の駐機判定を通す。別の弾の上書きや二重装填を拒否する。
- 元の向きと搭載位置を機体設定に保持する。組み立て済みラックの座標は機体のタイプライターハブからの相対位置で管理し、ライブのエンティティUUIDには依存しない。
- MSラックの残弾検出を追加。記録済みスロットに不足がある場合は発艦前点検で弾薬不足と判定する。

## 検証範囲

別環境の実際のSable機体、MS組み立て済みラック、MSロケット、CBC信管を使用。6種類それぞれについて、再装填、実物の各1個消費、向きの維持、誤ったアイテム・二重装填の拒否、補給後の内容からMS純正の投射物を生成できることを確認。ブロック取り付け型も6種類の再取り付けと信管装着を確認した。

スケマティックへの搭載情報のシリアライズを確認。今回の試験は保存データへの包含までで、再読み込み後の全機体・全搭載位置を使った発射試験ではない。整備員の歩行・在庫取得は既存の爆弾と共通の仕組みに接続したが、今回のロケット試験では再装填処理を直接呼び出しており、NPCの歩行から再装填までの通し試験は未実施。
