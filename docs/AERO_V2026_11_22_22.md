# v2026.11.22-22 見張り情報の保持・船内回転系の破損保護

## 見張り情報

見張り員ごとに、直近の完了した見張り結果を次の見張りまで保持します。従来の12秒の期限や測距履歴の整理だけで、攻撃目標の一覧・選択・砲の追跡から消えることを防ぎます。

次の見張りで対象を見失うと、その見張り員の報告を更新します。別の見張り員がまだ報告を保持していれば残ります。削除された船は対象から外れます。測距履歴が古い場合は最後の情報を残しますが、現在の正確な船の位置を無条件に取得する方式にはしていません。再起動をまたぐ発見情報の保存は今回の変更に含みません。

## 回転系の保護

Sable船内でCreateが速度・回転方向の衝突、速度増幅、過速・過剰な変動を検知した場合、軸や制御器を破壊する代わりに、その接続を一時停止します。200tick後に再接続を試します。根本的な回転系の衝突が残っていれば再度停止するため、ブレーキ・クラッチ・回転数の設定を確認してください。停止に伴うベアリング等の通常挙動まで無効化するものではありません。

`config/aerocannons-performance.toml` の `shipKineticConflictFuse=true` が既定です。falseで従来の回転衝突時の破壊に戻せます。地上の回転系、被弾や爆発による破壊は変更しません。

試験用の保存船のコピーで「ブレーキ解除 → キネティックバッテリー起動 → バッテリーから見て奥 → 手前」を順番に操作し、空気・ディーゼルを補充しました。修正前は回転系2か所が破壊され、修正後は440tickの試験で回転系破壊0、欠損0、からくりディスアセンブル0でした。

追加試験では、衝突保護が動作した後、18基の砲架の通常のレッドストーン更新処理へ、組み立て信号を維持したまま発砲信号を7回ON/OFFしました。実際に機関砲弾が生成されたことを確認し、800tick時点でも回転系破壊0、欠損0、からくりディスアセンブル0でした。NPCのリモコン入力を経由した試験ではなく、砲架への発砲信号とその後の挙動の確認です。全砲の装填・発射を保証する試験ではありません。

別の小さな試験構造体でも、実際のCreateの衝突処理から保護が働くこと、地上は保護しないこと、設定falseで無効化できることを確認しました。

v21の船底クリアランス対策、v18の乗員UUID再生成対策と専用サーバーDH負荷制限、通常額縁・Interiors大型座席の設計図許可を含みます。本番サーバーと参加用インスタンスには未適用です。
