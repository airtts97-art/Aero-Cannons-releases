# v2026.11.22-18 乗員の再生成ループとDH負荷への対策

## 変更

Nepheria Gloudの乗員復活で、同じUUIDがまだエンティティ管理に残っているときに新しい乗員を生成しないようにしました。存在する乗員を消す処理ではありません。

- 同じUUIDの生存乗員が見つかった場合は、重複した復活待ちを解除します。
- UUIDが管理中でも実体を取得できない、読み込み・解除の途中などでは、200tick待ってから再確認します。
- 乗員の追加が拒否された場合、待機データを消さず、200tick後に再試行します。
- 同一UUIDの復活待ちの重複をまとめます。通常の死亡時の1200tick（20TPSで約60秒）の待ち時間は維持します。
- 乗員のない名簿では追加のリスト作成を行いません。

DH（Distant Horizons）の対策は専用サーバーだけに適用します。クライアントやシングルプレイの描画設定は変更しません。

- realTimeUpdateDistanceRadiusInChunks：上限64チャンク
- generationRequestRateLimit：上限2回/秒
- syncOnLoadRateLimit：上限8回/秒
- distantGeneratorMode：PRE_EXISTING_ONLY（DH自身は未生成チャンクを新規生成せず、既存の地形からLODを作成）

元の設定が上限より小さい場合は維持します。DHのAPIによる起動中だけの上書きで、DistantHorizons.tomlを直接書き換えません。遠方の地形更新・LOD取得はゆっくりになります。通常のチャンク生成や近距離のブロック更新は止めません。

奈落版標準、試合環境リセット、復活待ち時間表示、MAPの向き変更などv17までの変更も含みます。既存の試合場を自動消去することはありません。

## 導入

1. サーバーを通常終了し、ワールドと現在のJAR・設定をバックアップしてください。
2. mods内の旧aerocannons JARを外し、このJARを1つだけ配置してください。他のMODは変更しません。
3. サーバーを起動してください。既存のconfig/aerocannons-performance.tomlには不足する設定が追加されます。
4. 参加者にも同じJARへの更新を推奨します。CurseForge用ZIPには依存MODを含む参加環境を収録しています。サーバー更新ZIPは更新JARと手順書のみです。

DHを入れていない場合はDH対策をスキップします。DHは3.2.0-b、Nepheria Gloudは配布名1.1.0（内部MODバージョン1.0.0）の構成で確認しました。別バージョンでは連携対象が異なる可能性があります。

## 設定で戻す場合

config/aerocannons-performance.toml の以下を変更し、再起動してください。

- crewRespawnDuplicateGuard = false：再生成対策を無効化して元の復活処理に戻す
- crewRespawnRetryTicks = 200：拒否・読み込み待ち時の再試行間隔
- dhServerMatchLimits = false：DHへの起動中上書きを停止する
- dhServerExistingChunksOnly = false：DHの生成モードだけを元の設定に任せる

## 確認範囲と限界

別環境の専用サーバーで、読み込み中のUUID、同じUUIDの既存乗員、追加を拒否された後の再試行、待機データの重複、通常の1200tick後の復活を確認。DHの実際の設定値と生成モードへの反映も確認しました。

開催先の船・人数を使った試合中の負荷比較は未実施です。TPSの改善率、Sableの読み込み・解除エラー自体の解消、メモリリークの解消は確認できていません。本番とこのPCのインスタンスへの自動適用はしていません。
