# v2026.11.21-7 — 船の反対側の乗員も更新対象に維持

v6の甲板上の登録機体検出・発艦整理要求・実寸の通路確認と、v5の衝突候補の空間分割を含む。

実測で、整理要員2人のワールド側チャンクがシミュレーション距離から外れ、EntityTickListにも含まれず更新が止まっていた。プレイヤーは更新対象、通信士も更新対象だったため、サーバー全体の停止ではなかった。

プレイヤーが乗る船（接続船を含む）または非スペクテイターが外形から32ブロック以内にいる船で、名簿に登録された乗員のワールド側チャンクに短期チケットを発行する。20 tickごとに更新し、更新がなくなれば60 tickで期限切れ。通常のワールド強制読み込み一覧には追加せず、離れた船を永続的には保持しない。

整備対象の再検索は、更新が間引かれても実行できる経過時間による20 tick間隔に変更した。

本番確認：適用前は整理要員の worldTicking=false、inTickList=false、更新回数が数千tickにわたり固定。適用後は両方trueに変化し更新回数の増加を確認。現時点で対象船1隻、更新対象チャンク5個。

Ｎ一番機体の既存飛行任務はユーザー指定で中止し、整理要員の対象を指定し直した。手動整理要求を保存済み。整理要員1人が実在するスッポンランチャーの保管場所への経路を探索し、もう1人は同じ機体を二重に作業しないため待機。牽引・発艦完了までは確認していない。

参加用インスタンスは、ゲームを強制終了せず、終了後にv7へ差し替える待機処理を設定。JARと177MOD入りCurseForge ZIPを更新。Sable UDPやMinecraftの移動確認・衝突検証は無効化していない。
